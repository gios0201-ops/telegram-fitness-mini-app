## Сценарии

1. Редактирование профиля, пересчёт, сохранение и перезагрузка.
2. Редактирование PPL, запись фактических весов/повторов и сохранение дневника.
3. Два замера, график с временной шкалой, таблица, рабочие веса в истории, reload.
4. Настоящий Telegram SDK с тестовым native bridge: CloudStorage, темы, отсутствие localStorage fallback.
5. Ошибка CloudStorage блокирует сохранение; сообщение успеха не появляется; обновление разрешает повтор.
6. Reduced motion, desktop, динамические Telegram theme/safe-area events.
7. Устаревший Telegram без переключения в демо; повреждённая запись остаётся на месте и экспортируется.

Модульные тесты дополнительно проверяют обе константы формулы, активность, поддержание без профицита, недопустимые значения, отрицательные углеводы, настоящие календарные даты, объём подходов, резервный лимит ключей, размер JSON, порционное чтение/экспорт, callback errors/false/таймауты, изоляцию двух независимых mock-хранилищ, ID guard и сохранение старых настроек до мутаций Bot API.

## Исправления, найденные проверками

- Приведены сигнатуры CloudStorage callback к SDK: результат может отсутствовать при ошибке.
- Dev-зависимости первоначальной ветки Vitest имели известные уязвимости; заменены актуальной веткой, lockfile пересоздан штатным npm, проверен `npm ci`. `--force` и `--legacy-peer-deps` не использовались.
- После перехода на Vite 8 выявлено различие CommonJS default export SDK в dev/build. Адаптер нормализует экспорт; содержимое SDK не менялось.
- Preview готовой сборки должен использовать тот же base path, что и build. Путь передаётся через `E2E_BASE_PATH`, и проверка включена в CI.
- Повреждённая анкета блокирует запись, но не скрывает возможность raw export.

## Граница верификации

Это локальные unit/browser/build проверки. Native Telegram bridge в браузерных тестах — mock; реальная изоляция аккаунтов Telegram, синхронизация разных устройств, haptics на телефоне, Android/iOS/Desktop WebView и Blob download не проверены на живых клиентах. Проверка двух mock-хранилищ не подменяет проверку двух реальных аккаунтов.

На этапе первоначальной локальной проверки GitHub Actions не запускались. При последующей публикации фактически проверены GitHub Actions на Node 22, Pages и публичный HTTPS URL, включая JS/CSS и браузерный smoke. Результаты: [отчёт публикации](publication.md). BotFather и live Bot API не проверены. Настройка бота требует отдельного разрешения.

Авторские схемы имеют анимированную подсветку групп мышц; полноценные анимации техники из сторонних источников не включены без проверки лицензии. Автоответ `/start` и фоновые напоминания находятся за пределами MVP.
