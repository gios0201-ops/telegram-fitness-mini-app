## Сценарии из ТЗ

Все 15 требований покрыты сценариями в `tests/e2e/workout.spec.ts`: полная начальная программа 8/8/7; открытие и возврат; один/три последовательных подхода; последний результат отдельно от рекорда; подстановка; аналитика; исправление; удаление с подтверждением/отменой; повторное открытие; переименование со стабильным ID; узкий экран; ошибка CloudStorage; v1-история; сохранение пользовательского плана. Дополнительно проверены повторные нажатия, расписание, ручное связывание архива и разрешение конкурирующих правок.

Сохранены проверки профиля/КБЖУ, графика веса, прогресса, экспорта, тем, safe area, reduced motion, устаревшего Telegram и повреждённого хранилища. Прежний сценарий общей формы тренировок адаптирован к новой записи отдельного подхода, проверки сохранения профиля, программы, тренировки и замеров остались.

Unit-проверки журнала: объём/рекорд/последний результат, размер и группировка страниц, резерв ключей, повтор с тем же ID, неизвестный результат callback и идемпотентный повтор, правка/удаление событиями, два writer, конфликт/явное разрешение, v1-чтение без миграционной записи, неизменность исходного JSON, переименование, неоднозначное имя, повреждённая цепочка и недоступный SDK. Дневник питания: расчёт массы порции, валидация, чтение/экспорт, редактирование/удаление/reload, native bridge без localStorage и ошибка без ложного успеха.

## Найдено и исправлено

- При расширении списка префиксов появилась ошибка перечисления физических ключей демо-localStorage. E2E обнаружил отсутствие данных при повторном чтении; исправлено и добавлен regression unit-тест.
- Для заполненной заметки и select расписания добавлены однозначные доступные подписи.
- Селекторы общей формы обновлены для нового экрана; карточки каталога отделены от карточек пользовательской программы, чтобы проверка её размера оставалась точной.
- Удалена браузерная автоматическая светлая тема: основной вариант тёмный, тема Telegram по-прежнему применяется динамически.

## Граница проверки

Telegram-сценарии используют реальный SDK и **имитацию native bridge**, а не настоящий аккаунт или облако Telegram. Браузерные проверки Chromium с мобильным viewport не являются проверкой iOS/Android Telegram. WebKit загружен, но на локальном хосте не хватает системных библиотек для его запуска; результаты WebKit/iOS не заявляются. Ручная проверка реальных Android/iOS/Desktop WebView, двух аккаунтов, синхронизации устройств, Blob-экспорта и физических haptics остаётся необходимой.

Нет CAS/транзакций CloudStorage; ограничения конкурентных записей и конечного объёма истории описаны в [training-compatibility.md](training-compatibility.md). Автоматического удаления или разрушительной миграции нет.

GitHub Actions и доступность нового Pages commit проверяются отдельно после push; локальные PASS не подменяют проверку фактической публикации. Сборка создаёт `release.json` с SHA из `GITHUB_SHA`; состояние jobs и этот SHA служат доказательством конкретной опубликованной версии. Историческая первая публикация описана в [publication.md](publication.md).

## Мобильная доработка

Добавлены сценарии `mobile.spec.ts`: установка полного плана только после просмотра/подтверждения поверх старой программы из трёх упражнений, отмена без записи, сохранение старого JSON и истории после перезагрузки; все 23 упражнения и мышечные группы; четыре полосы питания, отдельные формы, 24 скриншота пяти вкладок и упражнения. Проверена кнопка Telegram «Назад» через SDK bridge с платформой iOS. Unit-тесты дополнительно проверяют частичный сбой, неподтверждённую запись, устаревший просмотр, повторную установку и резервную копию текущей программы. Реальный iOS Telegram/Safari не проверялся.
