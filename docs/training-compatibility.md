# Тренировки: хранение и совместимость

## Интерфейс и программа

«Тренировки» → день Push/Pull/Legs → карточка → отдельный экран упражнения. Шапка содержит название, мышечную группу, диапазоны, авторскую схему спереди/сзади, сворачиваемую технику и типичные ошибки. Сразу за ней идёт форма отдельного подхода: вес, повторы, заметка, последний фактический результат и «Подставить». Повтор прошлого подхода — одна кнопка. Форма остаётся после сохранения; счётчик, история и анализ обновляются после callback CloudStorage и проверочного чтения. Максимальный вес не подменяет последний результат.

Анализ показывает количество подходов, внешний вес (максимум), сумму `кг × повторы`, число повторений, рекорд объёма одного подхода, сравнение последних двух результатов и таблицу динамики по датам. Для упражнений без внешнего отягощения 0 кг не включает массу тела. История позволяет исправить вес, повторы и заметку либо удалить подход с подтверждением.

Начальная программа из ТЗ: **Push 8, Pull 8, Legs 7**. Альтернативы в названии — один пункт, а не две обязательные записи. Диапазоны и технический отказ сохранены. Каталог доступен и пользователям со старой программой; отдельные упражнения можно добавлять в редакторе. По умолчанию понедельник Push, среда Pull, пятница Legs; остальные дни отдых/лёгкая активность. Расписание редактируется; ручной выбор дня работает независимо от календаря. Программа — шаблон, нагрузка выбирается пользователем.

Базовая тема тёмная, светлая Telegram поддерживается. Кнопки от 44 px, основная запись 56 px, поля от 16 px; safe areas и системный BackButton поддерживаются. Черновик сохраняется при возврате к списку в текущем сеансе. Используется history state без нового URL пути, поэтому GitHub Pages не требует backend-маршрутизации. Закрытие/перезагрузка сохраняет подтверждённые записи; несохранённые черновики не обещаются.

## Схема

- `fit_v1_profile`, `fit_v1_weight_*`, `fit_v1_food_*`: совместимы с предыдущей версией.
- `fit_v1_plan`: читается, новая версия его не заменяет автоматически.
- `fit_v1_session_*`: исходные тренировки сохраняются побайтно. Доступны в экспорте и отдельном архиве истории.
- `fit_v2_plan_Push/Pull/Legs`: изменения конкретного дня. Деление позволяет полной программе и длинным пользовательским подсказкам помещаться в значения до 4096 символов.
- `fit_v2_schedule`: семь дней недели.
- `fit_v2_log_<дата>_<writer UUID>_<номер>`: страницы событий, несколько подходов/изменений в одном ключе, до 50 событий и до 4096 символов JSON.

Подход имеет UUID, стабильный `exerciseId`, дату, `day`, `workoutId`, фактические вес/повторы, заметку и время записи. Для новых подходов `workoutId = дата + день PPL`: несколько заходов одного дня объединяются в статистике. Имя — снимок для истории, не постоянный идентификатор.

Добавление, исправление, логическое удаление и разрешение конфликта — события с собственным UUID действия. Исправление ссылается на прочитанную ревизию; удаление записывает `null`, исходная история остаётся. Повтор того же действия проверяется по ID и содержимому. Повторный ID с другим содержимым отклоняется. Двойные нажатия блокируются немедленно через ref, независимо от задержки React render.

У каждого открытия приложения собственный writer UUID. Устройства не перезаписывают страницы журнала друг друга. После заполнения страницы создаётся следующая; отдельного ключа на каждый подход нет. При конкурирующих исправлениях появляются две вершины истории; обе остаются сохранёнными, пользователь явно выбирает итог. Устаревшая правка после уже прочитанной новой ревизии отклоняется. Это не распределённая транзакция и не проверка конкурентного поведения реального Telegram сервера.

## Совместимость без разрушительной миграции

При первом чтении нет записей миграции, удаления или перезаписи. Полная программа используется только при отсутствии сохранённого плана. При наличии v1-программы сохраняются её состав, названия, ID и настройки; v2-план перекрывает только явно отредактированный день.

В v1-сессии не было ID упражнения. Связь строится только при одном совпадении в соответствующем дне по имени, прежнему имени после переименования или известному старому названию из каталога. Каждому старому подходу назначается детерминированный ID из ключа сессии и индексов. Неопознанные/неоднозначные записи доступны отдельными архивными упражнениями. Их можно связать вручную; добавляется событие, исходный JSON не меняется. Переименование программы сохраняет прежние имена в `legacyNames`, новая история продолжает ссылаться на ID.

Перед ручным связыванием экспортируйте JSON в профиле. Чтение старой истории само по себе не является физической миграцией. Успех сохранения проверяется callback и точным повторным чтением страницы. Ошибка, пустой ответ, false, неизвестный результат таймаута или несовпадение чтения блокируют запись до обновления данных; локального fallback в Telegram нет. Повреждённые записи блокируют загрузку, raw-экспорт остаётся доступным.

## Ограничения и сохранность

[Telegram CloudStorage](https://core.telegram.org/bots/webapps#cloudstorage) изолирует записи по пользователю и боту, допускает до 1024 ключей и 4096 символов на значение. Приложение использует резервный порог 900 с учётом чужих ключей. Чтение выполняется пачками по 50.

Из-за отсутствия compare-and-swap окно конкурентной перезаписи остаётся для анкеты, программы одного дня, замера одной даты и страницы питания. Проверка перед записью обнаруживает уже произошедшее изменение; она не атомарна. Страницы журнала между открытиями разделены writer UUID, конкурирующие правки подхода сохраняются как конфликт.

История конечна: логическое удаление не освобождает старые ключи. При лимите новые страницы блокируются, экспорт доступен; автоматической очистки, скрытого усечения или разрушительного уплотнения нет. Физическая очистка/импорт архива за пределами этой версии. Не обещаем бесконечное хранение внутри CloudStorage.

Материалы — авторский SVG; чужие изображения не скачивались. Каталог предусматривает поле лицензированного media для последующего добавления после проверки прав. Без backend нет автоответа `/start` и фоновых напоминаний; бот и его настройки не изменяются.
