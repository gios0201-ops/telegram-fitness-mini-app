## 2. Выбранная архитектура

Vite/React/TypeScript → статические assets → GitHub Pages. Telegram Mini Apps SDK включён в bundle через `@twa-dev/sdk`; runtime не загружает внешний CDN. SDK предоставляет native bridge для CloudStorage, темы, safe areas и haptics.

CloudStorage принадлежит паре бот/Telegram-пользователь, и изоляция выполняется Telegram. Локальная подстановка user ID не является авторизацией и не используется. Обработчика сообщений нет. Приложение открывается menu button/Main Mini App. Регистрация `/start` — метаданные списка команд, не auto-reply.

Анкета и программа — два ключа; каждая тренировка — отдельный UUID-ключ; масса тела — отдельный ключ даты. Это убирает общий растущий JSON и исключает частичную запись тренировочной сессии в несколько ключей. Размер одной записи/программы проверяется до отправки. Между устройствами профиль/план/замер даты имеют last-write-wins; транзакций/CAS CloudStorage не предоставляет.

Демо использует отдельный localStorage с явной маркировкой. В Telegram при сбое нет локального fallback. Некорректные данные не заменяются defaults; сохранение блокируется, доступен экспорт raw JSON. История не обрезается автоматически.

## 3. Минимальный состав изменений

| Файлы                                          | Назначение                                                |
| ---------------------------------------------- | --------------------------------------------------------- |
| `src/domain.ts`                                | Схемы, расчёты, демонстрационные данные, PPL              |
| `src/storage.ts`                               | CloudStorage adapter, лимиты, валидация, история, экспорт |
| `src/telegram.ts`                              | SDK, выбор режима, темы, haptics                          |
| `src/App.tsx`, `src/style.css`, `src/main.tsx` | Интерфейс и обработка ошибок                              |
| `scripts/setup-bot.mjs`                        | One-shot Bot API setup с dry-run/backup/ID guard          |
| `scripts/check-client.mjs`                     | Проверка известных шаблонов секретов в клиенте            |
| `.github/workflows/*`                          | Конечный CI/CD и отдельный ручной setup                   |
| `tests/*`                                      | Расчёты, CloudStorage, bot setup, E2E                     |
| `README.md`, `docs/*`                          | Инструкции, границы и проверяемый отчёт                   |

Zod используется для проверки внешних сохранённых данных и введённых значений. Новые зависимости и lockfile ограничены новым приложением. Dev-зависимости обновлены при обнаружении уязвимостей первоначально установленной ветки Vitest; существующие проекты не затрагивались.

## 4. Границы

Публикация тестовой версии выполняется отдельно от подключения Telegram. Запросы к реальному Bot API и изменения BotFather не входят в публикацию. Постоянные процессы, Docker, VPS и платные сервисы не используются. Результаты размещения и live-проверки фиксируются в отчёте о публикации.
