# Рост · Telegram Fitness Mini App

Статическое приложение для набора мышечной массы: React + TypeScript + Vite, Telegram Mini Apps SDK (`@twa-dev/sdk`), Telegram CloudStorage и GitHub Pages. Работает без VPS, Docker, платного сервера и постоянно включённого компьютера. Компьютер нужен только для разработки или одноразовой настройки бота.

## Что реализовано

- Анкета: пол для формулы, рост, вес, возраст, общая активность, набор/поддержание, профицит, нормы белка и жира.
- Миффлин—Сан Жеор, оценочный TDEE, калории и БЖУ с пересчётом при редактировании.
- Push / Pull / Legs: редактирование названий, мышц, подсказок, количества подходов и повторов; добавление/удаление упражнений.
- Дневник: дата, фактические килограммы и повторы каждого подхода. Последние рабочие веса подставляются по названию упражнения.
- Карточки с авторскими SVG-схемами и анимированной подсветкой мышц. Схемы условные; это не видео техники. Сторонних GIF, фото, видео или материалов без установленной лицензии нет.
- График массы с реальным временным интервалом между замерами, таблица, история тренировок и общий объём «кг × повторы».
- Telegram темы, смена темы во время работы, safe areas, haptic feedback при подтверждении/ошибке; мобильная и десктопная вёрстка, reduced motion.
- Экспорт JSON, удаление выбранных записей с подтверждением, проверка лимитов и ошибок CloudStorage.

Начальный профиль — мужчина, 20 лет, 175 см, 80 кг, умеренная активность (обычно 3–5 тренировок в неделю), набор массы. BMR = 1798,75, TDEE = 2788,06, профицит = 462, итог = **3250 ккал, Б160 / Ж80 / У472**. Углеводы округляются вниз: энергия округлённых макронутриентов отличается на 2 ккал. Профицит выбран для заданного демонстрационного старта и редактируется.

TDEE — оценка, не измерение и не гарантированная потребность. Коэффициент учитывает весь день. Используйте динамику веса за несколько недель для постепенной корректировки. Частота приёмов пищи не задаётся. Формула для взрослых; персональные медицинские назначения приложение не делает.

## Локальный запуск

Нужен Node.js 22.12+ (ветка 22) или 24+ и npm. Никаких токенов для разработки не требуется.

```sh
npm ci
npm run dev
```

Откройте адрес из вывода Vite. В обычном браузере включается явно обозначенный **деморежим** с отдельным `localStorage` (`fitness-demo-v1-*`). Это не Telegram CloudStorage и не синхронизация устройств. После запуска из Telegram используется только CloudStorage; при его сбое приложение не переключается на localStorage.

## Проверки

```sh
npm test
npx playwright install chromium
npm run test:e2e
npm run build
npm run check:secrets
npm run check:publish
npm audit
# Проверка готовой сборки с подкаталогом GitHub Pages:
VITE_BASE_PATH=/telegram-fitness-mini-app/ npm run build
E2E_PRODUCTION=1 E2E_BASE_PATH=/telegram-fitness-mini-app/ npm run test:e2e
```

Vitest проверяет формулы, валидацию, лимиты, повреждённые записи, таймауты, подтверждение сохранения и безопасность настройки бота. Playwright проверяет редактирование анкеты/PPL, дневник, замеры/график, сохранение после перезагрузки, темы и ошибки CloudStorage. В Telegram-сценариях используется настоящий SDK и тестовый native bridge. Это не проверка реальных Telegram-аккаунтов. Скриншоты создаются в `test-results/` (не коммитятся).

## Архитектура и сохранение

```text
Telegram → HTTPS GitHub Pages → статический React UI
                             → Telegram SDK → CloudStorage пользователя этого бота
GitHub Actions → тесты/сборка → Pages
локально или workflow_dispatch → одноразовый Bot API setup
```

CloudStorage изолирует данные по **пользователю и боту средствами Telegram**. На фронтенде нет самодельной авторизации по `user_id`, нет общего хранилища, токена бота и запросов к Bot API. `initDataUnsafe` не используется как доказательство личности. Код страницы публичен; персональные записи не включаются в сборку.

| Ключ                         | Содержимое         |
| ---------------------------- | ------------------ |
| `fit_v1_profile`             | Анкета             |
| `fit_v1_plan`                | PPL-программа      |
| `fit_v1_session_<uuid>`      | Одна тренировка    |
| `fit_v1_weight_<YYYY-MM-DD>` | Один замер на дату |

Лимиты Telegram: до 1024 ключей на пользователя бота, значение до 4096 символов. Приложение проверяет размер JSON и резервирует запас: новые ключи не создаются при общем количестве 900; существующие доступны для обновления. Лимит учитывает и чужие ключи этого бота. Удаление не затрагивает ключи вне `fit_v1_`. Чтение выполняется пачками по 50. Валидация схем блокирует перезапись повреждённых данных; исходные записи можно экспортировать даже при ошибке загрузки.

При ошибке, `false`-подтверждении или таймауте запись не объявляется успешной; сохранение блокируется до «Обновить данные». Таймаут не доказывает, что запись не произошла: сначала перечитайте облако. Тренировка имеет стабильный UUID на время заполнения формы; повтор не создаёт вторую запись. Изменения нескольких ключей не являются транзакцией. Одновременное редактирование анкеты/программы или замера одной даты на разных устройствах — last write wins; обновляйте данные перед редактированием на другом устройстве. Черновики форм не синхронизируются; сохраните их перед уходом с экрана.

Экспорт содержит личные данные, скачивается локально и не загружается на сторонний сервер. Некоторые Telegram WebView могут ограничивать Blob-скачивание; требуется проверить на целевых клиентах, альтернативно использовать Telegram Desktop. Автоматическая очистка истории отсутствует. Если лимит исчерпан, экспортируйте и вручную удалите выбранные записи.

## GitHub Pages и CI/CD

Проект подготовлен для **отдельного репозитория**, в корне которого находятся `package.json` и `.github/`. Репозиторий и Pages настраиваются отдельно от других проектов.

При самостоятельном развёртывании:

1. Создайте отдельный GitHub-репозиторий и загрузите эти файлы (без `node_modules`, `.env`, `dist`, `bot-backups` и секретов).
2. В `Settings → Pages → Build and deployment → Source` выберите **GitHub Actions**. Для бесплатного Pages используйте публичный репозиторий; доступность Pages для приватного зависит от тарифа.
3. Push в `main` запускает `.github/workflows/pages.yml`: `npm ci`, unit tests, Playwright, TypeScript, production build и проверку отсутствия известных шаблонов секретов в клиенте. Затем публикуется `dist`.
4. Pull request в `main` проходит проверки без публикации. `workflow_dispatch` на `main` позволяет повторить pipeline. URL возвращает `deploy-pages`.
5. Путь ресурсов автоматически задаётся как `/<имя-репозитория>/`; для репозитория `<owner>.github.io` — `/`. Для локальной проверки подкаталога: `VITE_BASE_PATH=/telegram-fitness-mini-app/ npm run build`.

Токен бота не передаётся в build job. Нет polling, webhook, циклов или обработчиков сообщений в Actions. CI/CD и ручная настройка — конечные задачи. Периодические уведомления не реализованы: Actions не имеют доступа к пользовательским CloudStorage и не должны работать как постоянный бот.

## Привязка URL через BotFather

После отдельного разрешения и успешной публикации:

1. Откройте официального `@BotFather`, выберите `/mybots` и нужного бота.
2. В `Bot Settings → Menu Button` (или через `/setmenubutton`) задайте имя **Открыть Рост** и полный HTTPS URL, `https://gios0201-ops.github.io/telegram-fitness-mini-app/`.
3. При необходимости включите Main Mini App через `Bot Settings → Configure Mini App` и укажите тот же URL. Названия пунктов зависят от клиента BotFather.
4. Откройте чат бота и запустите приложение через menu button или кнопку в профиле.
5. Проверьте запись профиля/тренировки/замера, закрытие и повторное открытие; второй аккаунт должен видеть собственные данные. Затем проверьте Android, iOS и Desktop, темы и haptics.

**Регистрация `/start` не создаёт автоответ.** Для постоянного ответа на текстовые команды нужен отдельный обработчик сообщений. Он за пределами MVP. Без него `/start` лишь отображается в списке команд, а приложение открывается кнопкой меню/профиля.

## Одноразовый скрипт Bot API

`scripts/setup-bot.mjs` по умолчанию только показывает план, без токена и сетевых запросов:

```sh
MINI_APP_URL=https://gios0201-ops.github.io/telegram-fitness-mini-app/ npm run setup:bot -- --dry-run
```

После явного разрешения на изменение бота задайте через безопасное окружение терминала `BOT_TOKEN`, `EXPECTED_BOT_ID` (числовой ID нужного бота) и `MINI_APP_URL`. Не вставляйте токен в команды, историю shell, `.env` проекта или аргументы процесса. Затем:

```sh
npm run setup:bot -- --apply
```

Скрипт проверяет `getMe` и ожидаемый ID; читает текущие команды/menu; сохраняет старые значения в игнорируемую папку `bot-backups/`; сохраняет существующие команды и добавляет `/start`, если его нет; устанавливает menu button. Webhook и существующие обработчики не меняются. Настраивается default scope команд/menu; scoped и языковые overrides остаются прежними. Две мутации не атомарны: при частичном сбое скрипт сообщает об этом, не обещая откат.

Для выполнения через GitHub:

- Создайте environment `telegram-setup`; рекомендуется ограничить его веткой `main` и включить required reviewers, если тариф поддерживает.
- Добавьте environment secret **BOT_TOKEN** и variables **EXPECTED_BOT_ID**, **MINI_APP_URL**.
- Запустите `One-time Telegram configuration` через `workflow_dispatch`: сначала `apply=false`, затем после проверки `apply=true`.
- Backup сохраняется как artifact `previous-bot-settings` на 7 дней, включая случай частичного сбоя. Backup не содержит токен.
- Для восстановления вручную верните команды и menu button из backup через BotFather либо одноразовые вызовы `setMyCommands`/`setChatMenuButton` в безопасном локальном окружении. Сначала сверяйте ID; скрипт не выполняет автоматический откат.

## Границы MVP

Нет постоянного сервера, обработчика `/start`, push-напоминаний, общей БД, тренерского доступа, платежей, синхронизации CloudStorage из Actions или автоматического назначения программ. Легальные сторонние анимации техники можно добавить только после проверки лицензии; сейчас есть авторская анимированная подсветка условной схемы.

Аудит окружения и решения: [docs/audit-and-architecture.md](docs/audit-and-architecture.md). Фактические результаты локальной проверки: [docs/verification.md](docs/verification.md).
